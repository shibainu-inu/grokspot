# 設計メモ：意図と仕組み

GrokSpot がどう動いているか、なぜそう作ったかをまとめます。

## 全体像

```
 ┌──────────────── Android（Kotlin） ────────────────┐
 │ GrokButtonService   ボタンの押し方 / 暗い部屋での画面オン・オフ │
 │        │ press                                     │
 │ MainActivity ── VoiceSession ⇄ wss://api.x.ai/v1/realtime │
 │        │  イベント名・音量（evaluateJavascript）           │
 └────────┼──────────────────────────────────────────┘
          ▼
 ┌──────────────── WebView（JavaScript） ─────────────┐
 │ voice.js  会話のイベント → 表情、入力待ちの表示             │
 │ life.js   会話していないときの暮らし                       │
 │ touch.js  タッチ → 目線・反応                             │
 │ actions.js 動作名 → 表情、だれが顔を動かすかの切り替え        │
 │ motion.js 体の動き・まばたき・目線・変形 ─┬─ grokbot.js（目）│
 │ fx.js     紙吹雪・虹色の軌跡・変形の部品 ─┘                │
 └──────────────────────────────────────────────────┘
```

音声とボタンのように端末の機能が必要なものは Kotlin、見た目はすべて WebView 側に置いています。顔は Web の技術で作るほうが調整しやすく、PC のブラウザでも確認できるためです。Kotlin 側はページに **イベント名だけ** を渡し、どの表情にするかはページが決めます。

## 顔を動かす担当

顔を動かすものは 3 つあり、同時に 1 つだけが担当します。

| 担当 | いつ | 切り替わり |
|---|---|---|
| voice.js | Grok と会話している間 | ボタンで接続すると担当になり、切断で外れる |
| life.js | 会話していない間 | `grokspot.act('idle')` で担当になる |
| 一時的な反応 | タッチの反応、起動時の目覚めなど | 終わると life.js に戻る |

`actions.js` の `act()`／`state()` が担当の切り替えを一手に引き受け、life.js を止めたり再開したりします。会話中は `idle` になっても life.js を再開しません（会話中の待機は「ユーザーの声を待っている」状態なので）。

## 音声会話（VoiceSession.kt）

- **接続**：`wss://api.x.ai/v1/realtime?model=grok-voice-latest` に API キーのヘッダーを付けて接続します。端末が自分でキーを持つ構成です（一人で使う専用端末を想定）。
- **セッション設定**：声 `eve`、サーバー側の発話検出（`server_vad`）、入出力とも 24 kHz の PCM、端末の言語の指示文（`res/values*/strings.xml` の `voice_instructions`）、関数 `set_avatar_state` を 1 つ登録します。
- **マイク**：`VOICE_COMMUNICATION` で 40 ms ずつ読み、base64 で送ります。
- **再生**：届いた音声を専用スレッドの `AudioTrack` に流します。再生キューには「ここまで鳴ったらイベントを出す」という目印も積めるようにして、表情の切り替えを **データが届いた時点ではなく、実際に音が鳴った時点** に合わせています。
- **終了**：ボタンをもう一度押す、60 秒間会話が動かない、アプリが裏に回る、のいずれかで切断します。常時接続にしないのは、料金と、テレビの音などへの誤反応を避けるためです。

### 割り込みができない理由

Echo Spot には `AcousticEchoCanceler` がありません。Grok の声をマイクが拾うと、サーバーは「ユーザーが話し始めた」と判定して自分の返事を止めてしまいます。そのため、エコーキャンセラーがない端末では **再生中はマイクの音を送らない** ようにしています（半二重）。エコーキャンセラーがある端末なら、話し始めた時点で再生を止める割り込みが働く作りになっています。

## 表情の連動（voice.js）

正式な仕様は [AVATAR-STATE-SPEC.md](AVATAR-STATE-SPEC.md)（Grok と共同でまとめた状態遷移仕様の Grok Voice API 版）です。ここでは要点だけをまとめます。

会話のイベントから自動で切り替えるのは、次の 5 つ（と切断）だけです。それ以外の表情をイベントから推測して割り当てることはしません。

| 状態 | きっかけ（Realtime API のイベント） | 備考 |
|---|---|---|
| `listening` | `input_audio_buffer.speech_started` | 常に最優先。8 秒以内に返事が始まらなければ待機に戻る |
| `thinking` | `response.created` | |
| `working` | 最初の `response.output_audio.delta` が **鳴り始めたとき** | |
| `searching` | `response.function_call_arguments.done`（`set_avatar_state` 以外） | |
| `idle` | `response.done` の音声を **鳴らし終えたとき** | |
| `idle` | 切断 | |

> `input_audio_buffer.speech_started` / `speech_stopped` は xAI のドキュメントに載っていませんが、実際には送られてきます（2026 年 10 月時点で確認）。

### Grok が自分で表情を選ぶ（avatar_state）

ニュアンス（聞き返すときの `curious` など）は、Grok 自身に選ばせます。

- **関数呼び出しで渡します。** Speak-to-Speak では応答が音声で返るため、`{"text": ..., "avatar_state": ...}` のような JSON を本文に混ぜると読み上げられてしまいます。関数 `set_avatar_state(state)` の呼び出しは音声にならないので、本文と完全に分離できます。
- 選べる状態は関数の定義で列挙しています（`happy` `excited` `curious` `confused` `surprised` `sad` `angry` `thinking` `working` `searching` `celebrate` `bored` `alerting` `notifying`）。ページ側でも名前を確かめ、知らない名前は無視します。
- **優先順位**：Grok が選んだ表情は、その応答の `thinking`／`working`／`searching` より優先し、最低 2 秒は表示します（「うん」のような短い返事では 0.8 秒）。ユーザーが話し始めたら `listening` が勝ちます。
- **余韻**：会話が応答の直後に終わったら、その応答で Grok が選んだ気持ちを 4 秒残してから待機中の暮らしに戻します。モデルには頼まず端末側で決めます（Grok との相談で決めた方針）。
- 応答が `set_avatar_state` だけで音声がなかった場合は、関数の結果を返してから `response.create` を送り、返事を続けさせます。

### 入力待ちの表示

| 表示 | 意味 |
|---|---|
| 画面の縁の青い輪がゆっくり明滅＋「話しかけてください」 | マイクが開いていて、話しかけてよい |
| 輪が明るく点灯＋「聞いています…」 | ユーザーの声を聞いている |
| 表示なし | Grok が考えている・話している（このときマイクは送っていない） |

Echo（Alexa）の光の輪にならい、顔とは別に「今話しかけてよいか」がひと目で分かるようにしています。

## 待機中の暮らし（life.js）

止まった絵ではなく、生き物のように見せるための仕組みです。

- **活動**：「状態の並び」として定義しています（例：鼻歌 `humming` → `happy`、何かに気づく `surprised` → `suspicious` → `curious`）。活動と活動の間は 15〜45 秒ほどぼんやり（`idle`）します。同じ活動は続けて選びません。
- **元気**：起きている間は減り（昼は約 45 分、夜は約 15 分で 0）、眠ると戻ります（約 20 分で満タン）。元気が多いと遊ぶ・跳ねる・落書き、少ないと退屈・うとうとを選びやすくなります。
- **眠り**：うとうと（`drowsy`）のあと、眠り込むか起き直します。夜（端末の時計で 22〜6 時）は朝まで眠り、ときどき寝返りを打つようにうとうとします。朝になって元気が戻ると目覚めます（`waking`）。
- 会話のあとは少し元気が増えた状態で再開します。

## タッチ（touch.js）

触れた位置を頭の中心からの距離（顔の単位、頭の半径は 114）で判定します。

| 位置 | 判定 | 反応 |
|---|---|---|
| 頭の外 | outside | そちらを見て興味を示す |
| 頭の上部 | pat（撫でる） | 喜ぶ・照れる・得意げ |
| 目のあたり | eye | びくっとして、驚く → 照れる／困惑 |
| 頭のそれ以外 | body | びくっとして、くすぐったそうに笑う |
| 3 秒以内に 5 回 | pester（連打） | 怒ってから、すねる |

どの場合も、目と頭がタッチの方向を向きます（目線・首の回転・体の傾き）。指を動かすと目が追いかけます。寝ていればどこを触っても起きます。会話中は目線とびくっとする動きだけにして、表情は会話に任せます。

5 秒の長押しはアプリ側（Kotlin）で検出し、Android の設定を開きます（ホームアプリにしたときの抜け道）。

## 体の動きと変形（motion.js / fx.js）

- xAI の記事 [Designing Grok Bot](https://x.ai/news/designing-grok-bot) で公開されているアバターの振る舞い（状態ごとの姿勢・まばたき・目線の動き、変形、紙吹雪、虹色の軌跡）を参考に、独自に実装しています。
- 体の動きはすべて減衰ばね（Spring）で目標値に近づけ、カクつかないようにしています。
- **変形**：特定の状態では頭が小さな点に縮み、記号の一部になります。

| 状態 | 変形 | 状態 | 変形 |
|---|---|---|---|
| thinking | 「・・・」の入力中ドット | sending | 点を送り出す |
| alerting | 「！」 | receiving | 点を受け取る |
| dictating | 音量で動く点の波 | uploading | 衛星が 2 つ周回する |
| orbit | 5 つの点が周回する | bouncing | ボールのように跳ねる |
| radar | 波紋が広がる | loading | 小さな頭が揺れ、虹色の軌跡が回る |
| progress | 進捗リングが埋まる | writing | ペンになって線を書く |
| spawning | 点が渦を巻いて集まる | powering-down | 明滅しながら輪が閉じる |

### 性能のための工夫

Echo Spot の処理能力は低く、初期の実装では SVG の属性を毎フレーム書き換えたところ 16〜40% のコマ落ちが出ました。そこで次のようにしています。

- 毎秒 30 フレームに制限し、目の描画も体の動きと同じフレームで行う（`manualFrames`）
- 頭や「！」の棒など大きな部品は、一度描いた絵を CSS の `transform` と `opacity` だけで動かす（GPU で合成される）
- 変形の部品・紙吹雪・軌跡は、頭の前後 2 枚の canvas にまとめて描く。何もないときは描き直さない

この構成で、すべての状態で 30 fps を保ちコマ落ちがないことを実機で確認しています。

## 端末まわりの判断

- **マイクオフボタンを使う理由**：Echo Spot には音量キー以外のボタンがこれしかなく、LineageOS では電源キーとして報告されます。電源キーのままではアプリが受け取れないため、キー配置で `BUTTON_1` に変え、電源の役目（画面オフ・電源メニュー）はユーザー補助サービスで肩代わりしています。
- **ユーザー補助サービスにした理由**：どの画面が出ていても（電源メニュー表示中でも）ボタンを受け取るためです。画面の内容は読まず、ウィンドウが切り替わったことだけを使って電源メニューの表示を判定しています。
- **暗い部屋での画面オフ**：5 lux 未満が 2 分続くと画面を消し、20 lux を超えるとつけます。会話中やタッチ中は消しません。
- **ロック画面の上に表示**：画面を消すとロック画面になるため、`showWhenLocked` で顔をその上に出しています。
